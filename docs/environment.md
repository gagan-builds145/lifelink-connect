# LifeLink environment reference

The managed workspace supplies the Convex deployment values. The checked-in
`.env.example` intentionally contains only the build-time Convex placeholders.
Everything below is the complete reference for a local Windows 11 setup.

> Never put server secrets in a `VITE_*` variable. Vite inlines those values into
> the browser bundle. Server secrets belong on the Convex deployment.

## Browser build-time variables (`.env.local`)

| Variable | Required | Placeholder | Purpose |
| --- | --- | --- | --- |
| `VITE_CONVEX_URL` | Yes | `https://your-deployment.convex.cloud` | Convex client URL printed by `bunx convex dev` |
| `VITE_LIFELINK_CONTACT_EMAIL` | Optional | `hello@example.org` | Public contact address on the homepage |
| `VITE_LIFELINK_CONTACT_PHONE` | Optional | `+91 20 0000 0000` | Public contact phone on the homepage |
| `VITE_AUTH_BG_VIDEO_URL` | Optional | `/media/auth-bg.mp4` | Override the bundled auth background video |

## Convex deployment variables (`bunx convex env set ...`)

| Variable | Required | Placeholder | Purpose |
| --- | --- | --- | --- |
| `CONVEX_SITE_URL` | Yes | `https://your-deployment.convex.site` | Convex Auth callback/site URL |
| `SITE_URL` | Yes | `http://localhost:5173` | Allowed auth origin in local development |
| `JWT_PRIVATE_KEY` | Yes | generated by Convex Auth setup | Signs auth sessions |
| `JWKS` | Yes | generated by Convex Auth setup | Public key set for session validation |
| `VLY_INTEGRATION_KEY` | For email OTP | managed by Freebuff | Sends 6-digit sign-in codes; also the fallback secret for the OTP gate |
| `OTP_GATE_SECRET` | Recommended | long random secret | Server-only bearer secret for the `/otp-gate` OTP rate-limit endpoint. Set a dedicated value in production. |
| `ML_SERVICE_URL` | For ML features | `https://your-ml-service.example.org` | Reachable FastAPI URL. Convex Cloud cannot use `127.0.0.1`. |
| `ML_SERVICE_TOKEN` | For ML features | long random secret | Bearer token shared with the Python process; never a `VITE_*` value |
| `RESEND_API_KEY` / `RESEND_FROM_EMAIL` | For email | provider values | Server-only Resend credentials |
| `TWILIO_ACCOUNT_SID` / `TWILIO_AUTH_TOKEN` / `TWILIO_FROM_NUMBER` | For SMS | provider values | Server-only Twilio credentials |

## Python ML process variables

| Variable | Default | Purpose |
| --- | --- | --- |
| `ML_SERVICE_TOKEN` | unset | Bearer token for `/health` and `/v1/*`. Required in the production image. |
| `ML_REQUIRE_AUTH` | unset | Set to `true` in production to fail startup when `ML_SERVICE_TOKEN` is missing. The Dockerfile sets this. |
| `LIFELINK_ML_ARTIFACTS` | `ml_service/artifacts` | Directory containing active model artifacts |
| `ML_CORS_ORIGINS` | `http://localhost:5173` | Comma-separated browser origins if calling the service directly. Wildcard `*` is refused at startup. Convex server calls do not need CORS. |
| `ML_RATE_LIMIT_PER_MINUTE` | `120` | Per-client/path request budget (10–10000). |
| `ML_REQUEST_TIMEOUT_SECONDS` | `20` | Hard model timeout per request (1–180 s). Exceeding it returns 504. |
| `ML_LOG_LEVEL` | `INFO` | Log verbosity. Access logs never include payloads or identifiers. |

## Drone SITL bridge variables (operator workstation)

| Variable | Default | Purpose |
| --- | --- | --- |
| `DRONE_BRIDGE_TOKEN` | unset | When set, `--token` must match before an upload is allowed. |
| `DRONE_BRIDGE_STATE_DIR` | `~/.lifelink-sitl` | Replay ledger and command audit log location. |
| `DRONE_MAX_RADIUS_KM` | `60` | Geometric simulation fence radius from the first waypoint. |
| `DRONE_MAX_MISSION_AGE_MINUTES` | `60` | Maximum age of a mission export (`issuedAt`). |

## Edge / WAF variables

No runtime secrets are read by the SPA for the WAF. Configure hostnames, TLS and
upstreams in `deploy/nginx/lifelink.conf`; see `docs/waf-deployment.md`.

`/livez` remains public and returns only service/version status; it exposes no model metadata. `/health` is authenticated when a token is configured.

## Example

```powershell
# Browser
Copy-Item .env.example .env.local
# then set VITE_CONVEX_URL in .env.local
```

## Database schema changes

Convex owns the schema in `src/convex/schema.ts`. There are no SQL migration files:

- `bunx convex dev` watches the schema and applies it to the development deployment.
- `bunx convex deploy` applies it to production.
- Convex validates documents on write (the app keeps `schemaValidation: false` only
  for template compatibility and validates every input in the mutation layer).
- Adding an index or table is a code change followed by `bunx convex dev --once`.
